# 合并总规划

日期：2026-09-11。状态：规划交付，待进入实现。

## 1. 核心决定

采用**一个 Next.js 前端 + 一个 FastAPI 后端 + 一个 SQLite 数据库 + 两个工作台**。
以班主任版后端为工程起点，迁入教学版的教学班、单科分析及作业评价能力；前端以教学版为起点，班主任页面按该设计系统重建。
两工作台采用逻辑数据分区：共享一套代码和部署，但业务记录有明确归属。仅班主任班与其对应教学班建立受控关联。
不采用 iframe 拼接两个站点，也不做两个应用数据库之间的自动双写。

这是基于源码结构的工程判断，不代表某个仓库整体更可靠。两者原本就使用相同技术栈；班主任版保留更完整的成绩和学生生命周期，而教学版最新上传链路主动过滤其他学科、停写总分。以教学版后端整体覆盖会损失班主任所需能力。

## 2. 已确认的产品边界

- 用户本人使用，一个教师身份兼任班主任和任课教师。
- 两个旧应用全部历史数据都保留，默认按来源工作台隔离。
- 用户补充确认：仅本人班主任班和对应教学班需要互通；其他班只是教学班。
- 关联班默认共享名册、任教学科成绩、该科作业；谈话/家访等档案默认仅班主任可见（实施默认）。
- 关联只表达具体班、学年、学科及有效期，不把全部同名或同学号数据全局合并。
- 所有页面使用教学版浅蓝科技风、侧栏、顶栏、卡片和移动端样式。
- 当前任教学科仍沿用教学版“一位教师一个任教学科”，可管理多个教学班。
- 首版不做学校多租户、多教师账号、复杂角色授权或 PostgreSQL 改造；数据表仍保留 owner/教师关联的扩展位置。
- 保留本地启动及 NAS Docker 部署两种方式。

## 3. 用户如何使用

登录后左上角切换「班主任 / 教学」，切换后仍在同一个应用内。

| 区域 | 班主任工作台 | 教学工作台 |
|---|---|---|
| 范围栏 | 学年、学期、行政班 | 学年、学期、任教学科、教学班/全部所教班 |
| 首页 | 全科概况、临界/薄弱/偏科、作业和谈话跟进 | 单科概况、各教学班表现、作业收交和评价 |
| 成绩 | 总分、多科、班级对比、频次和趋势 | 当前学科、教学班对比、单科频次和趋势 |
| 学生 | 行政班名册、学生管理、全科画像、换届 | 教学班成员、单科画像、成员变更和历史关联 |
| 作业 | 本行政班各学科汇总，关联教学班本学科作业可见 | 当前任教学科；仅关联班与班主任侧互通 |
| 档案 | 班主任谈话、观察、家访和跟进 | 教学观察和跟进；关联班共享需显式选择，默认不开放班主任档案 |
| 共享入口 | 数据导入、教师设置、备份、迁移状态 | 同一套入口 |

两个工作台分别记住上次筛选。切换不要求重新登录，不改变另一工作台的班级绑定。
学生在两个范围有显式关联时，画像提供“查看另一工作台画像”；不在目标范围则说明原因。
首次配置可以只启用一种身份，未配置的工作台显示配置引导，不能报错或展示全校学生。

## 4. 实施顺序与交付门槛

| 阶段 | 交付 | 进入下一步的条件 |
|---|---|---|
| P0 基线 | 独立合并工程、固定来源版本、原版基线结果、CI | 环境可复现；旧版失败已区分记录 |
| P1 契约 | 身份/学年/成员/作用域、数据库迁移骨架、API 模型 | 样例迁移可重复；无数据串班 |
| P2 外壳 | 教学风格统一外壳、双工作台、独立筛选 | 切换/刷新/双标签页均不串状态 |
| P3 成绩 | 统一上传入口、分区保存、关联班投影、两种成绩策略 | 关联班同一考试分别得到全科及任教学科结果，其他班保持隔离 |
| P4 学生 | 名册、换届、改号、档案和打印 | 同名/跨届/撤销/历史接续通过 |
| P5 作业 | 统一学科+种类+收交批次+评价 | 关联班共享事实统计一致，其他教学班隔离，未知状态明确 |
| P6 AI | 公共服务工具、隔离范围聊天、只读 MCP | 页面/API/工具口径一致且无法扩大范围 |
| P7 迁移上线 | 双库演练、差异报告、NAS 候选、切换及恢复演练 | 数据核对、完整验收、恢复验证完成 |

P1 后 P2 可与后端任务错开目录推进；P3、P4、P5 遵循共享模型所有权，不能同时改一份 models.py。
先形成“关联班导入一次 → 两个工作台查该班同一学生的允许数据”的纵向闭环，再迁移剩余页面，避免先铺满空壳。
每阶段使用合成数据可运行、可演示、可回归。P7 前不能称为历史数据合并完成。

## 5. 主要成本与不确定性

最大工作量是身份映射、作用域、作业语义及迁移核对，界面换肤不是主成本。
P0 完成后再以实际失败数量、数据规模估算工期；不按代码行数或工具品牌承诺天数。
尚未读取真实双库，考试重复量、身份歧义、原始 Excel 可用性、当前 NAS 数据量未知，均在 P7 预检实测。
教学库里已被旧上传丢弃的其他学科和总分不能凭空恢复；优先由班主任库补齐，必要时重导原文件。

## 6. 本次审查的边界

已读取 GitHub 当前源码、核心数据模型、上传/作用域/作业/身份流程、前端结构和测试配置。
没有对整个应用做运行时质量认证，没有运行完整测试，没有读取生产学生数据。
历史审查发现只用于生成回归场景；最新教学版智能录入已包含同批例外预处理，不能把旧缺陷报告当作当前版本结论。

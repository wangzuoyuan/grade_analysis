# 历史迁移与上线

## 原则

保留两个来源数据域，**仅本人班主任班与对应教学班建立明确关联**。数据库放在同一应用中，不等于跨域合并所有学生和考试。
本次未读取生产库，迁移数量和身份冲突尚未知。实现前后均保留可追溯报告。

## 迁移步骤

1. **源快照**：登记代码版本、schema、数据目录、SQLite/WAL 状态、上传原文件、备份、业务配置与迁移标记。使用 SQLite backup API 或停写后完整快照，不直接复制一个正在写入的 db 文件。两个来源计算文件摘要。
2. **只读预检**：逐表数量、孤立外键、重复学号、前缀学号、空学科、日期覆盖、未关联身份、名册与教学成员差异。报告只提交脱敏统计；原始数据保存在忽略的本地目录。
3. **空目标建库**：使用显式独立 EXAM_TRACKER_DIR，执行版本化迁移；源库从不被目标应用启动代码直接打开。
4. **分区导入**：H → homeroom，T → teaching。所有来源主键经过 SourceMap 重映射，不能直接拼接 teacher.id/exam.id/student_identity.id。
5. **身份与时期**：先保留域内原身份链；跨源同号/同名不归并。识别旧 `G1::`、`g1-`、TMP 和 `_anon:`，保留完整原 ID。年级不能替代入学届别，无法确定学年/班级的记录隔离待核实。
6. **班级关联预览**：选择本人行政班、对应教学班、学年、学科、共享历史起止；列成员交集/差异及候选身份对应。确认后仅为这些人建立 LinkedStudent。
7. **关联成绩核对**：关联班同场考试映射需结合日期、学年、考试类型、原文件指纹和明细。单科相同可共享规范事实；矛盾值列冲突，不按来源新旧覆盖。其他教学班即使同场考试也只留教学域。
8. **作业转换**：H subject → 学科，T subject → 种类。保留状态、评价、特殊记录、排除设置。未知分母不得补成已交。旧同一天多条记录不盲目压成一次作业，无法定批次则保留 legacy 批次及不确定标记。
9. **档案/配置/审计**：谈话、家访等按原域保留；阈值与学期按域映射。两个 Teacher 不盲目覆盖，保留 H 行政班绑定和 T 科目/班级。密码和 API key 经运行环境配置，不写迁移报告。
10. **撤销快照**：H RosterImportBatch/RolloverConfirmBatch 中 JSON 引用须逐项映射并验证。不能安全转换的旧批次保留只读审计，明确不支持直接撤销；新合并版批次必须可撤销。
11. **核对后发布候选**：输出分区保留量、共享量、冲突量、待核实量和缺失来源，不达到门槛不得切换生产。

## 可重复与中断恢复

MigrationRun 保存源摘要、转换器版本、阶段、计数和错误；映射键为 `(source_fingerprint, table, primary_key)`。
重复跑相同快照不新增业务记录；若源摘要改变，创建新迁移批次并核对增量，不能复用旧“已迁移”标记。
单阶段事务提交，失败回滚当前阶段；未通过最终验证的目标库不开放写入。
关联确认、值冲突决策单独留痕，可用相同决策重放演练。

## 数据验收

- 每个来源业务行都满足：已映射保留 / 经确认共享并有来源引用 / 隔离待核实；分类互斥，三者合计等于源行数，遗漏必须为 0。
- 源数据完整性检查与目标 `PRAGMA integrity_check`、`foreign_key_check` 通过。
- H 总分、多科成绩逐字段保留；T 其他教学班数据只在 T 域；关联班共享科目原值一致。
- 名册、状态、跟进待办、作业原始缺交条数对账；新模型导致统计变化时给出逐条解释，不为对齐错误旧口径修改真实数据。
- 边界样本覆盖同名不同人、跨届复用学号、仅姓名成员、转班、无成绩、有历史无当前记录、重复考试、同日多份作业。
- 核心未解决身份/成绩冲突阻止其进入共享，待核实记录仍完整保留，可查阅但不进入不确定统计。

## NAS 切换与回退

部署合并版使用独立 Compose 项目（建议 `performance_unified`）、新数据目录、独立备份目录和经检查未占用的端口；不复用旧 data 卷。
先用合成数据验证容器，再用隔离迁移副本验证候选站。保持旧应用可访问。
最终切换前暂停两个旧应用写入，生成最终一致快照并重跑迁移/核对；禁止三个站点同时写入后再猜哪个最新。
切换入口后检查登录、两工作台、关联班共享、其他教学班隔离、上传、作业、AI/MCP、下载和打印，以及绕过代理的本地健康与公网访问。
原更新脚本按自身所在目录解析路径；合并版项目名固定于配置，目录名不写死。旧栈的现有项目名、端口和实际挂载在上线当天实测。

回退演练必须实际恢复一份合并版备份并验证查询。上线初期保留旧站只读快照和最终切换点。
上线后若已有新写入，回退先停写、备份新库并导出新增/修订清单；不能只切回旧站就宣称无损，需经核对回放增量或明确暂存待恢复。
旧应用何时下线由用户在候选验收后决定，当前规划不删除旧容器、卷和目录。

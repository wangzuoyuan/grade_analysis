# 2026-09-29 用户验收问题清单与整改计划

> 背景：用户在测试环境（diagnosis-roadmap 工作树，`localhost:3000`，测试数据副本）
> 以「2025-2026 学年（顶栏）+ 学期设置=2025学年第二学期」验收 P0–P3 诊断能力，
> 反馈 7 类问题。本文件为逐项根因诊断与整改计划；**尚未动任何代码**。
>
> 环境事实（诊断依据）：
> - 测试库 `.test-data/dev/exam-tracker/db.sqlite`：学年 2025-2026(id=1)/2026-2027(id=2)；
>   行政班 高一6班(id=1,学年1)、高二6班(id=2,学年2)；**成绩事实全部在学年 1**
>   （homeroom 2905 行 + teaching 294 行，7 场考试），学年 2 无任何成绩。

## 一、问题与根因

### A1【P0】仪表盘「查看档案」点开 404

- 现象：仪表盘顶部「优先关注」学生名后的「查看档案」→ `localhost:3000/homeroom/students/55` → 404。
- 根因：`frontend/src/app/homeroom/students/[id]/` 目录下**没有 `page.tsx`**，
  只有 `report/` 与 `diagnosis-report/` 两个子路由；而
  `app/homeroom/action-summary.tsx:247,258` 与 `components/research/ResearchView.tsx:552`
  都把链接写到 `/homeroom/students/{id}` 本身。
- 整改：
  1. 三处链接改为 `/homeroom/students/{id}/report`（班主任域既有报告页）；
  2. 补 `[id]/page.tsx` 重定向到 `report`（防再有链接写错；教学工作台 `/student/[id]` 同查一遍）。
  3. 前端契约测试补一条：渲染 action-summary 时断言档案链接指向 `…/report`。
- 工作量：≈0.5h。

### A2【P0】学生档案页「历次考试各科明细 / 总分走势」为空

- 现象：`/homeroom/profile` 同一学生，学情诊断卡显示「有效考试 7 场」，
  但历次明细表「暂无成绩数据」、KPI「涵盖 0 门学科」「暂无总分记录」。
- 根因：**作用域参数不透传**。`HomeroomProfileView` 调 `getStudentReport(person_id)`
  不带任何 query（`lib/api-v1.ts:1546`）→ 后端 `_resolve_academic_year` 缺省取
  **最新学年 2026-2027（高二6班）**，而成绩全在 2025-2026 → 查空；
  同页诊断卡显式传 `scopeQ.academic_year_id=1` → 有数据。同页两口径互相矛盾。
- 整改：
  1. `getStudentReport` 透传 workspace 学年（与同页其它请求一致）；
  2. **顺带全库排查**：grep 前端所有「不带 academic_year_id 调学生/成绩域端点」的调用点，
     统一从 `useWorkspace().filter` 取值透传（后端默认=最新学年，只应作为兜底而非实际依赖）；
  3. 后端可选加固：报告端点响应中带出 `academic_year_id`，前端不一致时提示。
- 工作量：修复 1h + 排查 1h。

### A3【P0】班主任工作台「计算相关性」按钮永远点不了（死锁）

- 现象：作业看板「作业提交率 × 成绩相关性」卡的计算按钮灰色不可点。
- 根因：`components/homework/CorrelationCard.tsx:259`
  `canQuery = effectiveSubject !== '' && examName != null`；班主任域
  `effectiveSubject = applied.subject`（:183），初始恒为 `''`，而**唯一给
  `applied.subject` 赋值的入口是被禁用按钮自己的 onClick**（:361）→ 逻辑死锁，
  不填学科永远不可点，填了学科（subjectDraft）也不生效。
  （教学域用 `scopeSubject` 自动带出，不受影响。）
- 整改：
  1. 门控改用草稿值：班主任域 `canQuery = subjectDraft.trim() !== '' && examName != null`，
     onClick 语义不变（点击即应用并查询）；
  2. 输入框旁加提示「输入作业学科（如：物理）后可计算」；空学科禁用时按钮 title 说明原因；
  3. 契约测试：填入学科草稿后按钮可点（现测试框架 test:ui 补用例）。
- 工作量：≈1h。

### A4【P1】教研看板「什么都没有」

- 现象：`/homeroom/research` 聚合卡全零。
- 根因（两层）：
  1. 页面默认选中下拉第一项「干预队列（0 人）」（`ResearchView.tsx:312`
     `setCohort(options[0]?.value)`），而干预队列要求
     `ws_student_note.status ∈ {open,done,dismissed}`——测试库（=生产快照）
     **130 条档案 status 全 NULL**（C4 之前的历史档案，按设计不算干预记录）→ 0 人全零；
  2. 类型队列实际存在（Wave E 冒烟 38 个，全部诚实标注 current_time_point），
     但藏在下拉里且无引导，用户无从发现。
- 整改：
  1. 默认队列改为**第一个非空队列**（优先有成员的类型队列），空干预队列仍可手选；
  2. 空队列时聚合区给引导文案：「暂无干预建档记录——可在学生档案的干预卡建档；
     或选择下方类型队列回看」；
  3. （产品决策，另行确认）是否提供「历史档案批量标记为干预」入口，或 C4 迁移时
     提示补录 status；不改判定口径本身。
- 工作量：1–2h（不含产品决策项）。

### A5【P1】学情类型分布无详情可点

- 现象：首页「学情类型分布」只有静态条形图；「优先关注」行只有类型徽章+依据文字，
  看不到具体学生姓名，也不能点开名单。
- 根因：`HomeroomDiagnosisOverviewCard`（`DiagnosisCard.tsx:621`）按设计只做聚合，
  无下钻交互；优先关注行未渲染姓名（仅 main_type + basis）。
- 整改：
  1. 每个类型行可点击 → 展开该类型学生名单（姓名 + 链接到学生报告页，依赖 A1 修复）；
  2. 「优先关注」行补学生姓名并链接；
  3. 数据无需新增请求（逐生 types 结果已在内存，含 person_id）。
- 工作量：2–3h。

### A6【P1】偏科口径说不清（用户问「百分比变化以什么为基线」）

- 现象：诊断卡「偏向：化学（+10.36 个百分点）」被理解为"与上次考试的百分比变化"。
- 实际口径（后端 `features.py:629-668`，非 bug）：
  - **基线 = 同一场考试里该生自己的主三门总分年级百分位**；
  - 偏差 = 该科年级百分位 − 自身总分百分位（**单位是百分点**，不是百分比变化，
    也不是环比、不是与班级均分比）；
  - 判偏科阈值 20 个百分点（`SUBJECT_WEAKNESS_PCT_DIFF=0.20`）；
    连续 ≥2 场偏科 → 「严重/持续偏科」。
- 整改（文案，不改计算）：
  1. 诊断卡「偏向/偏科」行尾注一句：「= 该科年级百分位 − 本人总分年级百分位（同场比较）」；
  2. 班级卡「严重偏科（化学）」等理由同样补短句或统一 tooltip；
  3. 报告页已有完整口径句（`DiagnosisReport.tsx:542`）保持不变。
- 工作量：≈1h。

### A7【P2】界面英文描述

已定位的英文露出点（用户「所有板块都有」的来源）：

   （`ResearchView.tsx:370-371,515`）等；

4. 技术词汇入副标题：「features + types 端点」「calc_version」等（多张卡片副标题）。
- 整改：

  3. Sidebar 副标题改中文（或删除）；副标题技术词汇改用户语言

### A8【P1·贯穿】学期/学年语义混乱（多个问题的共同背景）

- 用户把「学期设置」（作业学期=2025学年第二学期）当作全局学期；实际存在三个
  互不同步的"当前时间"：顶栏学年选择器（2025-2026）/ 作业学期设置（第二学期）/
  后端缺省（最新学年 2026-2027）。A2 的空明细、以及用户「设了学期为什么还这样」的
  困惑都源于此。
- 整改：
  1. A2 的透传修复是第一刀；
  2. 「学期设置」卡片与顶栏学年选择器各自的作用范围写明（学期设置仅作业窗口；
     成绩类页面跟随顶栏学年）；
  3. （可选，产品决策）顶栏直接显示当前生效口径「2025-2026 学年 · 成绩视图」，
     减少误解。
- 工作量：文案 1h（不含产品决策项）。

## 三、验证方案

1. 每项修复配前端契约测试（`npm run test:ui`）或后端 pytest，全量回归
   （后端 944 passed 基线、前端 191 基线不回落）；
2. `刷新测试数据.command` 重建副本后，按本文件「现象」逐条复测；
3. 偏科/队列等口径不变项：只加文案，不动计算与既有断言（含用户裁决的
   缺考跳过=连续进步保留口径）。

## 四、明确不做（除非用户另拍板）

- 不改偏科/队列/连续性的任何计算口径（本轮全是入口、透传、交互、文案问题）；
- 历史档案批量转干预记录（A4-3）另做产品决策；
- 顶栏口径显示重构（A8-3）另做产品决策。
